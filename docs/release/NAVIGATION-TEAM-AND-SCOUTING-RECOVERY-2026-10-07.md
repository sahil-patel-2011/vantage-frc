# Navigation, team departure and scouting recovery

Status: source changes reviewed; candidate NOT built, tested, migrated, merged or deployed. This document records behavior to verify, not acceptance results.

## Implemented source behavior

- Navigation uses 28 px primary icons on 44 px plates, 26 px expanded destination/search icons, readable labels and at least 44 px action targets. Destinations remain grouped by task and filtered by team permissions. Inner tools keep their parent workbench highlighted. The team chip opens Your teams; settings and shortcut editing scroll with destinations; sign-out has its own footer. Short landscape screens can scroll the entire drawer. Drawer materials retain transparency preferences, dark mode, focus trapping and closing motion.
- Home uses the real saved board and actual widget responses. The priority card is compact and a generic scouting shortcut disappears when the priority already opens scouting. A task-count brief no longer repeats a visible task widget, and setup prompts do not overlap the first-week card or layout editing. The three-column setup prompt has its required icon again. Creating a task remains a distinct action from viewing tasks. Scouting uses the actual active event key, not its display name; both match and pit forms must exist before scouting is described as configured. Delegated scouting leads reach form setup before stale assignments. Board menus close on Tab and support Home/End.
- Dashboard reads and mutations enforce team sign-in/MFA policy, including before upstream event hydration. Unauthorized responses clear the private board and preserve the server's reason; late denials cannot clear a newer team/board. Recovery distinguishes account outages, expired sessions, team access and authenticator requirements. Authenticator requirements open Security with the team and safe return destination. Security has bounded requests, duplicate-action protection, response acknowledgement, explicit recovery-code retention, custom destructive confirmations and rejection of stale refreshes. A signed-out Security request returns private 401; verification does not show before enrollment or before recovery codes are acknowledged.
- Sign-in with an invitation no longer advertises a competing team-code route or waitlist. Password/reset/recovery screens omit unrelated acquisition controls. Team-code lookup has bounded requests, duplicate-submit protection and preserved details on an unconfirmed response. Public signup remains subject to the existing December 1 date, explicit enablement and production-verification gates; those were not bypassed.
- Your teams has a self-departure flow with confirmation. Owners get an ownership-handover destination. Migration 0715 atomically removes only the caller's membership and access grants, revokes duplicate pending invitations and kiosk scan enrollment, and audits the departure. Team work and the person's account remain. The operation shares the organization lock used by handover/role changes; owners and the last administrator cannot depart this way. Retry acknowledgements are idempotent.
- Downloaded team views require verified membership, rather than merely a signed-in user ID. Known departure blocks offline team reads, retains unsent personal reports, invalidates session caches and signals other scoped tabs. An old in-flight membership result cannot undo a departure; fresh membership is required to restore access after rejoining.
- Event drafts retain their report ID, original published form, source and answers. Older forms can be fetched by ID under existing tenant/authentication checks. Unreadable questions do not get replaced by a newer form's questions. Storage failures keep the open answers visible and block target switches that would lose them. Own match and pit reports can reopen as corrections; newer drafts win over older saved answers.
- Personal report history incorporates newer queued corrections after reload. Client-ID collisions and older queued revisions preserve the original/newer report. Rejected event reports have a Review answers action; a correction removes the rejected row only when its replacement commits. Discard requires confirmation and cannot discard a rejected revision that changed while the prompt was open.
- Queue refreshes follow committed writes, cross-tab notifications, focus and visibility instead of a five-second scan that periodically caused session requests. No automatic GitHub or Vercel workload was added.
- Practice scouting separates editing next-report details from the current report. A new robot, match or set of questions gets a new report ID and fresh answers after confirmation. Closing/reopening details keeps current answers. Late saves keep newer edits open. Rejected reports stay queued until a corrected revision commits. Migration 0714 grants only author-scoped updates to answers and revision time; report identity and questions cannot be changed through that correction path.
- Scouting lead requests have progress states, duplicate protection, bounded waits and response acknowledgements. Conflict history has distinct loading, failure and confirmed-empty states. Winners, trust and official flags reset with account/event scope; older requests cannot replace newer conflict history or a new event's sync status. Official checks retain the acknowledged report's client, team, robot, match, event and form identity, appear only beside that report, and are labelled as last-upload checks. Formula weights use current match-form numeric fields; ordinary scouts do not see a lead-only save control.
