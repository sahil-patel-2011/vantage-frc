## Compatibility and review

### Assignments follow-up

The canonical Assignments page now presents one match board with saved assignee names, report authors/counts, lead reassignment controls and one collection link per robot. The repeated gap-action list was removed. Range assignment and schema-mapping warnings use labelled disclosures. Touch targets are at least 44px in the source styles, controls wrap and shrink for smaller containers, and status indicators remain quiet. Manual refresh is the default; optional minute updates pause when hidden. The range editor retains entered values across filter refreshes and explains removed scouts or out-of-filter bounds.

The existing navigation destination `/scout-coverage-live` now opens assignment editing by default; `view=review` retains missed-report accountability, coverage thresholds and coordinator alerts. `/scouting/lineup` redirects into that same workspace with all query values preserved. Share links carry the shown event, focus match and qualification filter. Coverage review now shares the assignments membership/authentication guard and validates persisted outcomes, while hosted acceptance remains unexecuted.

Coverage reads and writes enforce current membership and team authentication policy. Strict JSON action shapes, browser-origin and size checks, actual schedule slots and current assignees bound writes. Range writes derive the event from their first match and use it for preview, conflicts and the returned board. The three assignment publishers share an event transaction lock before reading conflicts; shift publishing also refuses departed scouts and robot slots outside the selected event. The legacy trust rotation refuses conflicts instead of silently saving them. These source changes add no migration or storage switch.

Assignment acknowledgements include the action, new/unchanged counts and explicit refused items; stale reassignment returns 409. The client validates scope and outcome before success, ignores stale reads, prevents overlapping writes and requires refresh after uncertain saves. Denied reads clear the displayed downloaded view. Account/team/event/filter device snapshots use the shared cache's variant argument and never delay live fetches; cached boards are read-only. Watchlist ordering remains useful within a match while match windows follow the actual chronological schedule.

Unexecuted regression sources cover origin and role denial, team authentication, event derivation, current membership, schedule targets, partial range refusals, stale swap, idempotent acknowledgement, response validation, custom-event bounds, duplicate/event-separated range compaction, assignee/report attribution and chronological windows. ### Scouting quality consolidation and official-check correction

Scouting Quality is now the canonical workspace for official checks, scout consistency, alliance review, the current scout's pick-list impact and lead-controlled form checking. Legacy Accuracy/Cross-Validation pages and collection Trust/Impact links redirect there, preserving team/event/filter query context. Hub redirects retain working filters and the resolved team; search absorbs old accuracy terms and retains the old alias's permission scope. Collection keeps match, pit, transfer and conflict review tasks; Forms and Assignments own their editing/management controls. The quality screen uses shared headers, keyboard tabs associated with their panel, wrapping controls, disclosures and source-level 44px targets. Exact-candidate visual acceptance remains unexecuted.

Quality reads and writes have bounded requests, generation guards, scope/shape validation and private responses. Non-JSON access denials clear the shown view. An unavailable or uncertain view is read-only until refreshed. Source-rule saves require a team-owned original schema/question, a checking baseline and a transaction lock, then confirm the returned question/state. Pit observations cannot be enabled as match official checks. Meeting seating uses a real calendar date and 1–10 scouts, rejects impossible dates, requires three comparable official checks and current team membership, confirms returned scout identities and avoids repeat notifications. It adds selected scouts while explicitly retaining existing seats. Unused preferred-source editing and duplicate assignment/publication controls are removed from this screen, with stored metadata preserved.

The evaluator no longer treats alliance foul totals or configured keys for another robot as robot evidence. Phase point totals, attempted-climb fields and obvious capability questions are not outcome comparisons. Deep/shallow/parked and other distinct outcomes are no longer collapsed into agreement. Missing or unobservable attempted-failure answers remain noncomparable. Corrected hard checks carry a private `[robot-check-v2]` marker in existing stored detail; the marker is stripped from scout-facing descriptions. Earlier hard checks remain stored but do not count toward confidence, meeting seats, contradiction stripping or AI evidence. Video checks use the same marker. New reports and corrections that change a report generate the current checks; identical replay does not re-evaluate old reports. Hosted validation and a deliberate historical recheck procedure remain required.

Private Edge, Quality, pick feedback and shared strategy/agent validation reads use matching tenant ownership, current evaluator evidence and the original form's enabled rules. Soft Statbotics predictions and unavailable comparisons cannot enter the confidence denominator. Optional confidence hints in collection now validate the team/event and response shape, discard unconfirmed hints, bound the request and ignore superseded replies. This is source behavior, not executed production proof.

Legacy point-comparison helpers now default individual robot reports to unverifiable, even if robot and alliance points happen to coincide. Saved old run verdicts are not reused; run identities, snapshots and promotions remain stored. Unsupported accuracy snapshots return 409 instead of saving a fake leaderboard. Legacy APIs/actions and rotation history still need further security/recovery/capability review; storage preservation does not establish complete UI parity.

Alliance review now returns the whole played qualification event, with progressive twenty-match rendering and an explicit flagged/all filter. No rows after the old forty-match cutoff are hidden. Scope/shape validation, request generations and timeouts protect reads; access denial clears data and outages return 503 rather than a successful empty setup. Missing observations keep neutral status styling, and allocated robot shares are labelled estimates rather than official robot measurements. An explicit refresh also exists in setup states. This pass does not measure event-scale responsiveness.

Existing calibration contracts now require current evidence and disabled-rule exclusion.
